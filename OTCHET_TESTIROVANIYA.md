# Отчёт по тестированию

**Проект:** веб-платформа «ФКН Хаб · ВГУ» (темы, посты, комментарии, модерация).  
**Дисциплина:** Технологии программирования.  
**Дата прогона:** 21.05.2026.  
**Среда:** Windows 10, Python 3.12.10, pytest 9.0.3.

---

## 1. Цель тестирования

Подтвердить соответствие реализованного функционала требованиям ТЗ: авторизация и роли, управление контентом, социальные механики, фильтрация и поиск, автоматическая модерация текста, админ-панель. Зафиксировать результаты ручных и автоматизированных проверок.

---

| № | Объект | Модули / маршруты |
|---|--------|-------------------|
| 1 | Регистрация и вход | `/register`, `/login`, `/api/login`, `/api/register` |

---

## 3. Уровни и методы

- **Модульное** — автотесты `pytest` на сервисы без БД.  
- **Интеграционное** — HTTP smoke-тест Flask test client (при доступной PostgreSQL).  
- **Системное (ручное)** — 16 тест-кейсов по основным сценариям (авторизация, контент, модерация, лента).

Техники: классы эквивалентности, граничные значения (длина пароля, цена, размер файла, причина удаления ≥ 8 символов).

---

## 4. Автоматизированное тестирование

### 4.1. Запуск

```powershell
# Модульные (по умолчанию в CI/локально)
pytest tests/ -v -m "not integration"

# Полный прогон с проверкой GET /
$env:INTEGRATION_TESTS="1"
pytest tests/ -v
```

### 4.3. Покрытие автотестами

| Модуль | Что проверяется |
|--------|-----------------|
| `post_fields` | Разбор цены, валидность Telegram и URL |

| `integration` | `GET /` → 200, HTML |

Автотесты **не** заменяют ручную проверку UI, RBAC и админки — эти сценарии в разделе 5.

## 5. Ручное функциональное тестирование

Выполнен основной набор из **16** сценариев (TC-01 … TC-16): регистрация с подтверждением пароля, вход (модалка и страница), темы, посты трёх типов, вложенные комментарии, мат и токсичность, лайк, гость без комментариев, скрытие комментария модератором, удаление поста админом с причиной, поиск и фильтр ленты, выход.

| Показатель | Значение |
|------------|----------|
| Всего сценариев | 16 |
| Пройдено | 16 |
| Провалено | 0 |
| Заблокировано | 0 |

**Уточнения после доработок:** TC-01 дополнен проверкой поля «Подтвердите пароль» на клиенте и сервере; TC-13 соответствует **мягкому** скрытию комментария staff (`mark_deleted_by_moderator`).

## 6. Нефункциональное тестирование (ориентировочно)

| Критерий | Норма ТЗ | Результат (ручной замер) |
|----------|----------|---------------------------|
| Загрузка главной | ≤ 2 с | ~1,2 с |
| AJAX-лайк | ≤ 300 мс | ~150 мс |
| Адаптивность | Bootstrap 5 | Корректно на desktop / mobile |
| Безопасность паролей | PBKDF2 | Хеш в БД (`auth_passwords.py`) |
| XSS | Экранирование Jinja2 | Подсветка поиска через `escape` + `mark` |

Нагрузочное тестирование на 100 одновременных пользователей **не проводилось** (вне объёма курсовой).

## 9. Выводы

1. Модульные автотесты проходят стабильно; интеграционный smoke-тест подтверждает старт приложения и ответ главной страницы при работающей БД.  
2. Основные функциональные сценарии по ТЗ проверены вручную, критических расхождений не осталось.  
3. Рекомендуется перед релизом: прогон `pytest tests/ -v` и выборочный прогон 16 ручных кейсов после миграций БД.

**Заключение:** система **готова к демонстрации и развёртыванию** в учебной среде при выполнении инструкции в `README.md`.
